# 縦スクロール型シューティングゲーム 実装仕様書

作成日：2026年10月11日  
仕様バージョン：1.0  
用途：Codexなどの開発支援ツールに渡す実装仕様書

## 1. 仕様の扱い

- **確定要件**：ユーザーが指定した内容。実装で必ず満たす。
- **提案仕様**：未指定部分を補完した案。変更可能だが、追加の指定がなければ初期実装の既定値として採用する。
- **将来拡張**：初期実装に含めず、基本機能の完成後に検討する。

本書の数値、操作方法、技術構成、演出、セーブ方式は、明記した確定要件を除きすべて提案仕様である。通貨やポイントの名称は未確定で、本書では仮に「クレジット」と呼ぶ。

## 2. ゲーム概要

プレイヤーが戦闘機を操作し、画面上方から出現する敵を弾やビームで倒す縦スクロール型シューティングゲーム。敵が落とすクレジットを回収し、武器を強化しながらステージクリアを目指す。

基本サイクル：敵の出現 → 移動・攻撃・回避 → 敵の撃破 → クレジットの回収 → 武器の強化 → より強い敵との戦闘。

## 3. 確定要件

| ID | 要件 | 完了条件 |
| --- | --- | --- |
| R-01 | 縦スクロール型シューティングゲームである | 戦闘エリアが縦方向に進行し、プレイヤーが戦闘機を操作できる |
| R-02 | 戦闘機が弾・ビームで攻撃する | 弾とビームの両方が使用でき、命中した敵にダメージを与える |
| R-03 | 敵が画面上方から現れる | 上端側から出現した敵を攻撃して撃破できる |
| R-04 | 敵を倒すと通貨またはポイントを落とす | 撃破地点に回収可能なアイテムが出現する |
| R-05 | 落とした通貨・ポイントを回収できる | 戦闘機で回収すると所持量が増える。撃破だけでは所持量に加算されない |
| R-06 | 回収した通貨・ポイントで攻撃を強化する | 回収した資源を使って武器の性能を上げられる |
| R-07 | 強化例として弾数増加を実装する | 1回の発射が1発から2発に増える強化が存在する |

## 4. 初期実装の範囲【提案仕様】

- 1人用、オフライン、1ステージのゲームとする。
- PCブラウザで遊べる構成を第一候補とする。
- 1回のプレイは約3分。最後にボスを出現させ、撃破でクリア。
- プレイヤー機、通常敵3種類、ボス1種類、弾、ビーム、敵弾、クレジット、強化画面を実装する。
- 初期段階は図形や仮素材で成立させ、画像・音声の制作を待たずに遊べる状態を作る。
- ゲーム内課金、オンライン対戦、アカウント登録、ランキング送信は初期実装の対象外。

## 5. 操作とプレイヤー【提案仕様】

| 操作 | 入力 | 動作 |
| --- | --- | --- |
| 移動 | 矢印キー／WASD | 戦闘エリア内を上下左右に移動 |
| 攻撃 | 自動 | 選択中の武器を上方向に連続発射 |
| 武器切替 | Space | 弾とビームを切り替える |
| 強化画面 | U | 戦闘を一時停止して強化画面を開く／閉じる |
| 一時停止 | Esc | 一時停止／再開。強化画面では戦闘へ戻る |
| 決定 | Enter／クリック | メニュー項目や購入を確定 |

- 初期HPは3。HPが0になるとゲームオーバー。
- 移動速度は毎秒280論理ピクセル。斜め移動でも速度は同じにする。
- 戦闘機は画面外に出ない。初期位置は画面下部中央。
- 被弾時にHPを1減らし、1秒間無敵にする。接触ダメージにも適用する。
- 見た目より小さな当たり判定を使い、機体の中心付近を被弾範囲とする。
- 背景を下方向へ流し、上方向に飛行している印象を作る。
- モバイルのタッチ操作・ゲームパッド対応は将来拡張とする。

## 6. 武器とダメージ【提案仕様】

弾とビームはゲーム開始時から選択可能。選択中の武器だけを発射し、それぞれの強化レベルは切替後も保持する。

### 6.1 弾

- 初期状態：1発、ダメージ1、発射間隔0.25秒、速度毎秒600論理ピクセル。
- 上方向へ直進し、敵1体に当たったら消える。初期実装では貫通しない。
- 2発以上の場合は機体中心に対して左右対称に発射位置を配置する。

### 6.2 ビーム

- 初期状態：幅12論理ピクセル、毎秒4ダメージ。
- 機体前方から上端まで伸び、範囲内の敵に継続ダメージを与える。
- 複数の敵を貫通する。弾より攻撃範囲が狭く、照準を合わせ続ける必要がある。
- ビームダメージは「毎秒ダメージ × 経過秒」で計算し、描画速度で威力が変わらないようにする。
- 切替時はビームを即座に停止する。既に発射された弾は通常どおり移動する。

## 7. 敵とステージ【提案仕様】

| 種類 | HP | 行動 | 攻撃 | 撃破時クレジット |
| --- | --- | --- | --- | --- |
| 小型機 | 2 | 上方から直進して下降 | なし | 10 |
| 中型機 | 6 | 左右に揺れながら下降 | 下方向へ単発弾 | 25 |
| 重装機 | 15 | 上部で短時間停止し、再び下降 | 3方向の弾 | 50 |
| ボス | 180 | 上部を左右移動 | 単発・扇状攻撃を交互に使用 | 200 |

- 通常敵は画面上端の外側から出現する。ボスも上方から進入する。
- 通常敵が画面下へ通過してもHPは減らさず、撃破報酬を逃した扱いとする。
- 0〜60秒は小型機中心、60〜120秒は中型機を追加、120〜180秒は重装機を追加。
- 出現間隔の初期値は順に1.2秒、0.9秒、0.7秒。敵種の配分は調整可能にする。
- 180秒で通常敵の新規出現を停止。残った通常敵が撃破または画面外へ退出した後にボスが進入する。
- ボス撃破後はダメージ処理を止め、残ったクレジットを自動回収してリザルトへ進む。
- HPが0になったフレームではゲームオーバーを優先し、同時撃破によるクリアとの二重遷移を防ぐ。

## 8. 回収と成長【提案仕様】

### 8.1 クレジットの回収

- 敵の撃破地点に、報酬額を持つアイテムを1個出現させる。
- アイテムは毎秒90論理ピクセルで下へ移動し、画面外へ出たら消える。
- 機体から半径40論理ピクセル以内に入ると機体へ引き寄せ、接触した時点で回収する。
- 一度回収したアイテムを再回収できないようにする。
- 所持クレジットと、そのプレイ中に回収した累計クレジットを別々に管理する。

### 8.2 強化購入

Uキーで強化画面を開くと、敵・弾・アイテム・ステージ時間をすべて停止する。購入は所持クレジットを消費する方式とし、自動強化にはしない。

| 強化対象 | 初期性能 | 購入順の性能 | 各購入の費用 |
| --- | --- | --- | --- |
| 弾数 | 1発 | 2発 → 3発 → 4発 | 50 → 100 → 200 |
| 弾の威力 | 1 | 2 → 3 | 100 → 200 |
| 弾の発射間隔 | 0.25秒 | 0.20秒 → 0.15秒 | 100 → 200 |
| ビーム威力 | 毎秒4 | 毎秒6 → 毎秒9 | 100 → 200 |
| ビーム幅 | 12 | 18 → 24論理ピクセル | 75 → 150 |

- 各系統は表の順に購入し、途中の段階を飛ばせない。
- 現在の性能、次の性能、費用、残高を表示する。
- 残高不足と最大強化済みの項目は購入不可にし、理由を表示する。
- 購入時は残高確認・消費・レベル更新を一度の処理で行い、連打による二重購入を防ぐ。
- すべての敵種が最低報酬を落とすため、弾数強化だけでも最初の段階を試せるようにする。
- この表は調整用の仮値。プレイ確認で敵HP、出現数、回収量と合わせて調整する。

### 8.3 リトライ時の扱い

武器強化と所持クレジットはそのプレイ限りとする。リトライではHP、武器、残高、敵、アイテム、ステージ時間を初期化する。永続強化は将来拡張とする。

## 9. 画面とUI【提案仕様】

| 画面 | 必要な表示・操作 |
| --- | --- |
| タイトル | ゲーム名、開始、操作説明、音量設定、ハイスコア |
| 戦闘 | HP、所持クレジット、スコア、武器名と強化段階、経過時間、操作案内 |
| 強化 | 購入一覧、現在／次の性能、費用、残高、戦闘へ戻る |
| 一時停止 | 再開、音量、タイトルへ戻る |
| リザルト | クリア／ゲームオーバー、スコア、撃破数、累計回収量、到達時間、リトライ、タイトル |

- ボス戦ではボスHPバーを表示する。
- スコアは買い物用残高とは別とし、「撃破した敵の報酬額合計＋クリア時1000点」で計算する。購入でスコアは減らない。
- 被弾、回収、購入、撃破を短い視覚効果で伝える。被弾無敵中は機体を点滅させる。
- 文字とアイコンを併用し、色だけに状態の意味を依存させない。
- 音声は任意。未用意でもゲームを動作させ、効果音やBGMは後から追加できる構成とする。
- ブラウザのフォーカスが外れたら自動で一時停止し、入力状態を解除する。復帰後は明示的な再開操作を待つ。

## 10. セーブ【提案仕様】

- 保存対象：ハイスコア、音量、操作説明を確認済みかどうか。
- 初期実装ではプレイ途中の状態、クレジット、武器強化を保存しない。
- ブラウザ版はローカル保存を使用し、保存形式にバージョン番号を付ける。
- ハイスコアはリザルトで更新する。設定は変更時に保存する。
- 保存データの破損、保存禁止、容量不足などが起きてもゲームは継続可能にする。
- 不正な値は既定値へ戻す。オンライン同期は行わない。

## 11. 実装構成【提案仕様】

既存プロジェクトに技術や規約があればそれを優先する。新規実装の場合は、TypeScript＋HTML Canvas＋Viteを候補とする。特定の技術の使用は確定要件ではない。

### 11.1 分担する機能

- ゲーム状態管理：タイトル、戦闘、一時停止、強化、リザルトの遷移。
- 入力：移動、切替、メニュー操作、フォーカス喪失への対応。
- プレイヤーと武器：HP、移動、発射、強化性能の反映。
- 敵とステージ：出現スケジュール、行動、攻撃、ボス進行。
- 戦闘判定：衝突、ダメージ、撃破、無敵時間。
- 回収と購入：アイテム移動、残高、購入条件、強化レベル。
- UIと保存：画面表示、設定、ハイスコア。

### 11.2 データと更新規則

- 論理画面は480×800。表示サイズに合わせて縦横比を保って拡縮し、余白を設ける。
- 座標・速度・当たり判定は論理画面の単位で扱う。
- プレイヤー、敵、発射物、アイテムに一意なIDを持たせる。
- 敵HP、速度、報酬、武器性能、強化費用、出現設定は調整用データにまとめる。
- 描画と更新を分離し、時間基準で処理する。長時間の停止後に大量の更新が走らないよう経過時間を制限する。
- 戦闘中のみゲーム時間を進める。メニュー入力と戦闘入力は状態ごとに扱う。
- 撃破処理と報酬生成は敵ごとに一度だけ実行する。
- 画面外の弾・敵・アイテムを除去し、再開始時には前回のオブジェクトを残さない。
- 通常弾は円または矩形、ビームは縦長矩形として判定し、最初から画像単位の精密な判定は行わない。

## 12. 実装段階と完了基準【提案仕様】

### 段階1：最小の戦闘

機体の移動、通常弾、上方からの敵出現、ダメージ、撃破を実装する。画面上で敵を狙って倒せることを確認する。

### 段階2：必須の成長サイクル

ドロップ、回収、残高表示、強化購入、1発から2発への変更、ビームと武器切替を実装する。R-01〜R-07をすべて満たすことを確認する。

### 段階3：1プレイの完成

敵弾、HP、無敵時間、通常敵3種類、ボス、クリア、ゲームオーバー、リトライを追加する。開始から終了まで一連のプレイを行えることを確認する。

### 段階4：UI・保存・調整

タイトル、操作説明、設定、一時停止、リザルト、ハイスコア保存、表示サイズ対応を完成させる。初回プレイヤーが説明を見て遊べる状態にする。

### 段階5：演出と拡張

画像、効果音、BGM、追加ステージ、永続成長などを検討する。段階4までの完成を先に優先する。

## 13. 受け入れ確認

### 確定要件の確認

- [ ] 戦闘機を操作し、縦方向に進行する戦闘を遊べる。
- [ ] 上から出現する敵を弾とビームの両方で倒せる。
- [ ] 敵を倒した場所に回収アイテムが現れる。
- [ ] アイテムを回収する前には残高が増えず、回収すると増える。
- [ ] 回収した資源で武器を強化できる。
- [ ] 弾数強化を購入すると、1回の発射が1発から2発に変わる。

### 提案仕様を採用した場合の確認

- [ ] 購入時に正しい費用を引き、残高不足や最大段階では購入できない。
- [ ] 強化画面と一時停止中は敵、弾、アイテム、ステージ時間が進まない。
- [ ] 被弾の無敵時間中にHPが連続で減らない。
- [ ] ボス撃破でクリア、HPが0でゲームオーバーとなる。
- [ ] リトライ時に前回の残高、強化、敵、弾が残らない。
- [ ] フォーカス喪失で停止し、復帰時に移動キーが押されたままにならない。
- [ ] 再読み込みで設定とハイスコアを復元できる。保存失敗時も遊べる。
- [ ] ウィンドウサイズを変えても画面比率と当たり判定が保たれる。

## 14. 調整・将来拡張

ゲーム名、見た目、敵の密度、難易度、報酬量、強化費用は仮設定として調整する。初期実装では本書の値で進め、実際のプレイで「早い段階で2発を体験できるか」「弾とビームに使い分けがあるか」「回収と回避に選択が生まれるか」を確認する。

将来拡張の候補：複数ステージ、難易度選択、武器追加、ボスの攻撃段階、永続強化、タッチ操作、ゲームパッド、画像・音楽の差し替え。
