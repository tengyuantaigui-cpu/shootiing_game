# BGM・操作ボタン修正報告（2026-10-11）

## 原因

装備・強化・設定を停止対象の paused に変換し、BGM選曲側も paused/shop を無音にしていた。スマホの pointerup は共通 onclick を通らずSEを省略していた。共通ボタンは非同期の AudioContext.resume() 完了を待たずにSEを発火して初回音を失っていた。また、一時的なresume拒否が音響全体を永久無効化していた。設定が戦闘中に非表示で、CHARGEと同じGridセルを使っていたため、未取得時に左下が空いていた。

## 再生仕様

タイトル/title、通常戦闘/battle、ボス/boss、エンドレスPHASE 6以降/endless。装備・強化は直前の曲を50%、設定は100%、ポーズは25%のBGM音量で継続。リザルトではファイルBGMを停止し既存の合成結果ジングルを一度再生。OFF・BGMミュート・全体ミュートは結果ジングルにも優先する。曲切替はファイル0.18秒、合成0.15秒のフェード。読み込み失敗時は合成BGMへ戻り、エンドレスは既存battle合成曲を使う。

背景でContextを中断し、復帰だけでは再生せず次のユーザー操作で再開する。音声有効化が拒否されても次の操作で再試行する。通常画面に診断情報は出さない。URLに `?audioDebug=1` を指定すると開発コンソールに構造化ログを出す。

## 操作・SE

装備／強化、設定／PAUSEの2×2。CHARGE所持中はその上に全幅の保持ボタンを置き、メニュー中も無効化して表示することで4ボタンの位置を保つ。PC専用操作説明はモバイルで非表示。既存セーフエリア余白を使用。

ボタン・装備・ポーズ・戻るはconfirm、メニュー移動・設定変更はmove、購入はpurchaseのみ、購入不可はdenied。pointerupと互換clickの重複を抑止し、同じSEは既存クールダウンと発音上限で連打を制限。SE音量・全体ミュートを継承し、BGM OFFでもSEは独立して動く。

## リロード時の音声有効化

初期表示で自動再生を試行し、ブラウザが拒否・保留する場合はタイトルに音楽開始ボタンを表示。最初のタップ・クリック・キー操作でresumeを再試行し、自動再生の保留Promiseが操作を妨げないよう修正。開始後にボタンを隠す。iOS Safari/PWAで操作前の自動再生は保証できない。
